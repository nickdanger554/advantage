# StoreAdOps Claude package 0.6.5

## Scope

The directory review for published 0.6.4 (`bf8161c`) reported the non-blocking
`PRIVACY_URL_MISSING` note. Both READMEs already linked the policy, but the
manifest did not declare `privacyPolicyUrl`. This metadata-only patch sets it
to the existing public URL, `https://app.storeadops.ai/privacy`, and keeps the
marketplace and plugin versions aligned.

The independent `ASSETS_PASSED_UNREAD` note says the well-formed PNG was accepted
without being interpreted as code; its printable text was screened. It is not
an image failure. Keep the existing website-matching logo unchanged. The
portal's separate icon-review status is not changed by this patch.

No skill, MCP endpoint, tool, OAuth setting, permission, provider operation,
privacy-policy content, license or submitted OpenAI package changes are included.
The new offline tests live outside `storeadops/` and are not bundled executable
plugin components.

## Validation and release boundary

Before publication:

- Run `python3 -m unittest discover -s tests -v`.
- Run strict Claude validation for the marketplace root and `storeadops/`.
- Verify the unchanged privacy URL returns HTTPS 200 without authentication.
- Verify the skills, MCP configuration, license and logo match 0.6.4 exactly.
- Review the scoped diff for secrets and unrelated changes.

Preparation checks passed on October 4, 2026 (America/Los_Angeles): five offline
metadata tests; strict root and plugin validation with an isolated official
Claude Code 2.1.289; unauthenticated HTTPS 200 from the privacy URL; and a zero
diff for all four skills, MCP configuration, license and PNG against `bf8161c`.
The existing global Claude CLI was not upgraded. These are package checks, not
new OAuth, model-conversation or provider-write tests.

The [official manifest reference](https://code.claude.com/docs/en/plugins-reference#directory-listing-fields)
documents `privacyPolicyUrl` as a directory field in `plugin.json`, not a
marketplace-entry field. Claude Code 2.1.281 or newer validates these directory
fields without an unknown-field warning. Do not remove the field to satisfy an
older validator.

Local validation does not prove that the directory rescanned or published this
version. After owner approval, merge the reviewed patch, use **Check for new
commits** in the existing StoreAdOps submission, and verify the exact new
commit/version and refreshed findings. Do not create a duplicate submission,
change credentials, accept new terms, or claim the older scan has been cleared.

## Rollback

The prior public baseline is 0.6.4 at
`bf8161c58038d2df04c20ef8a1c924f7ec671f76`. If a rollback is necessary, revert only
this release's package changes in a reviewed commit and publish a higher version;
do not rewrite tags. Removing the privacy declaration would restore the review
note, so retain it unless the owner explicitly approves an alternative.
